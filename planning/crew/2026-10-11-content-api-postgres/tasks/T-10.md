# T-10: Kiểm hình dạng nội dung khi nạp bằng model pydantic dùng chung (correction từ reviewer mối nối M1)

- **ID · tier · model**: T-10 · T2 · `crew-impl-standard` (sonnet, balanced) — instance mới
- **Objective**: content.json sai hình dạng (thiếu field, sai kiểu) phải bị CHẶN lúc `load_content`, không được nạp vào DB rồi làm mọi app parse lỗi và âm thầm rơi về cache.
- **Owned files**: `backend/app/content_schema.py` (mới), `backend/app/load_content.py`, `backend/app/content_api.py` (CHỈ thêm `response_model` cho `GET /content`), `backend/tests/test_load_content.py`
- **Forbidden files**: mọi file khác (mobile/**, main.py, tables.py, migration, các test khác).
- **Acceptance criteria**:
  1. `content_schema.py`: model pydantic khớp TỪNG KEY/KIỂU hợp đồng `/content` (PLAN.md) và `Content.fromJson`/`*.fromJson` ở `mobile/lib/domain/models.dart` + `content.dart` (đọc để đối chiếu; bắt buộc giống: Example.note `str | None`, indent_level `int`, mọi mảng là list[str], exercises là dict id → Exercise, file.exercise_ids list[str]); `extra="forbid"` cho phần công khai. Model `ContentPayload` (version + themes + exercises) và model nguồn có thêm `judge: {solution: str, cases: list}` cho mỗi bài.
  2. `validate()` trong load_content: chạy model nguồn TRƯỚC các kiểm hiện có; lỗi → `ValueError` nêu đường dẫn field (vd `exercises.split-chunks.challenge.small.caption`), DB không đổi (không xoá gì).
  3. `GET /content` có `response_model=ContentPayload` (không đổi JSON trả về — test hiện có `test_content_matches_source_without_judge` phải còn xanh).
  4. Test: thiếu `challenge.small.caption` → ValueError + DB giữ bản cũ; `indent_level` là chuỗi → ValueError; key lạ trong block → ValueError; `note` null hợp lệ; content.json thật vẫn nạp được.
  5. `cd backend && .venv/bin/python -m pytest -q` xanh toàn bộ.
