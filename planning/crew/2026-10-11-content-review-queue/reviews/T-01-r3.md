## Finding

**M1 [Major] Project mới có module "chuyển vào" (không phải module tạo mới) không approve được. Reject bất kỳ mục không liên quan sẽ tự reject project đó.** `backend/app/review.py:449-455` (`_companions`) và `:509-515` (`reject`).
- Cơ chế: `_companions` và `with_module` chỉ đếm module có `action == "create"`. Project mới có module cấp 1 là module có sẵn được kéo sang (action `update`, `theme_id == pid`, `parent_id None`) thì:
  1. Approve project → áp ra project rỗng → `InvalidResult` ("cần ít nhất 1 module").
  2. Approve module → `DependencyMissing` (cần duyệt project trước).
  3. Hai bên chờ nhau; chỉ còn cách reject.
  4. `reject` tính `new_projects - with_module` trên TOÀN BỘ hàng chờ, không chỉ phần liên quan tới mục đang reject.
- Bằng chứng (script `scen.py` và `scenD.py`, draft hợp lệ, `validation_errors == []`):
```
A rows [(project npX create), (module doc-storage update)]
A approve fail project npX invalid
A approve fail module doc-storage dependency_missing Cần duyệt project 'npX' trước
D reject unrelated file (airline-flight-py) -> {'status': 'rejected', 'also': [1259, 1260]}   # kéo cả project npX và việc chuyển doc-storage
left: []
```
- Tác động:
  - Admin tạo project mới rồi kéo một module sẵn có vào đó sẽ không bao giờ duyệt được.
  - Chỉ cần reject một mục hoàn toàn không liên quan là mất luôn project và việc chuyển module, không báo trước.
  - Ca C: project có cả module tạo mới lẫn module chuyển vào, reject module tạo mới → cả project và việc chuyển module bị reject theo (`also: [project, doc-storage update]`). Kéo theo vì project chết là hợp lý, nhưng gom nhầm với ca trên.
- Lỗi này không làm hỏng live. Chỉ mất mục đang chờ và kẹt hàng chờ, và reject vẫn dùng được.
- Cách sửa:
  - `_companions`: với project create, kéo thêm module `update` có `after.theme_id == row.item_id` và `parent_id is None`.
  - `reject`: chỉ xét project nào vừa mất module nhờ mục đang reject (hoặc cascade của nó). `with_module` phải đếm cả module `update` chuyển vào.
- Test cần bổ sung: tạo project mới + chuyển một module có sẵn vào → approve project thành công, `also` chứa module. Và: reject một mục không liên quan khi hàng chờ có project loại này → project còn `pending`.

**m1 [Minor] Cùng gốc với M1.** Reject trong ca C bỏ cả việc chuyển module, và `also` không báo gì ngoài id. Sửa theo M1 là đủ; không cần việc riêng.
