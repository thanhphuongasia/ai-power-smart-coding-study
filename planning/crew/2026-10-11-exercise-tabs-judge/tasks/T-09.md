# T-09: Tab Code — notebook ô khoá + ô TODO, Run → judge → kết quả → Bài tiếp theo (mobile)

- **ID · tier · model**: T-09 · T2 · `crew-impl-standard` (sonnet, balanced)
- **Objective**: Thay stub `code_tab.dart` bằng notebook kiểu Jupyter theo mockup (artboard Code + Run).
- **Owned files**: `mobile/lib/features/exercise/code_tab.dart`, `mobile/lib/features/exercise/run_result_view.dart` (mới), `mobile/test/code_tab_test.dart` (mới)
- **Forbidden files**: `backend/**`, `planning/**`, mọi file khác (dùng API sẵn có: `templateSegments`/`mergeCells`, `CodeInput(showBars:false)` + `CodeToolbar`, `judgeClientProvider`, `ProgressController`, `nextExerciseAfter`, `runBlock`/`normalizeCode`).
- **Acceptance criteria**:
  1. Notebook từ `templateSegments`: ô khoá (nền xám đậm hơn, icon khoá "có sẵn", highlight Python, prompt `[1]:`), mỗi ô TODO: dòng mô tả (tag label vàng + title + "trong hàm"/"trong vòng for" suy từ indentLevel 1/2) + `CodeInput(showBars:false, keyPrefix:'cell-<label>')`. Một `CodeToolbar` dùng chung ở đáy. Ghi chú "Không cần thụt lề...".
  2. Draft mỗi ô lưu qua `saveDraft` (key = label), mở lại tab còn nguyên. Nút Gợi ý cho ô đang focus (`useHint`, hiện hint tiếp theo, ≤3).
  3. "Run tất cả": ô trống → không gọi judge, báo "Ô X còn trống" và viền ô đó. Đủ ô → `mergeCells` → `judgeClientProvider.run` (spinner, chặn bấm lặp).
  4. `RunResultView` (Out): badge `k/n test đạt` hoặc trạng thái lỗi; mục "Code đã ghép" (mở sẵn) mỗi dòng có cột nguồn (A/B/C hoặc trống cho dòng khoá); danh sách test `>>> call` → actual, dấu đạt/không (expected hiện khi fail); stdout nếu có; `unavailable` → thông báo + "Thử lại".
  5. Ô sai: `error.line` → `lineOrigin[line-1]` → viền đỏ + chữ "Lỗi ở ô X: <message>" (INV-05). Lỗi ở dòng khoá → nói "lỗi ở phần có sẵn (thường do ô phía trên)". Fail không có line → ô khác mọi `acceptedAnswers` (so bằng `normalizeCode`) hiện "Kiểm tra lại ô này" — ghi rõ là gợi ý.
  6. CHỈ `status == passed` mới gọi `markPassed`. Pass → nút "Bài tiếp theo" (`nextExerciseAfter`, điều hướng `/exercise/<id>` bằng pushReplacement) hoặc "Về danh sách" nếu không còn bài; kèm "Sửa lại".
  7. Test (FakeJudgeClient override provider): ô trống chặn Run; passed ⇒ markPassed + nút Bài tiếp theo dẫn tới overlap-chunks; syntax error line ⇒ đúng ô viền đỏ; failed ⇒ không markPassed; unavailable ⇒ Thử lại; không overflow 375×667 khi bàn phím mở.
- **Validation command**: `cd mobile && flutter test test/code_tab_test.dart && flutter analyze`
- **Evidence command**: `git status --porcelain -- mobile/lib/features/exercise/code_tab.dart mobile/lib/features/exercise/run_result_view.dart mobile/test/code_tab_test.dart`
- **Thứ tự thực hiện**: (1) Run + map lỗi về ô + gating markPassed (rủi ro cao); (2) notebook UI; (3) RunResultView; (4) layout test.
